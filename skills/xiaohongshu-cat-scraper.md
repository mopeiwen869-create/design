node "${CLAUDE_SKILL_DIR}/../web-access/scripts/check-deps.mjs"

## 采集流程总纲

```
0. 风险告知 → 用户确认
1. 加载词表 + 排除词表
2. 遍历搜索词（上限 20 词）
   ├─ 2.1 搜索页 → 切"最新"排序 → 滚动加载
   ├─ 2.2 第一段预筛（列表卡片级）：
   │      时间 → 保留"1个月前"及以上
   │      点赞 → 取前 50%
   ├─ 2.3 第二段筛（开详情页，低成本）：
   │      精确时间 → 超 6 个月 → 关
   │      收藏数 → 低于动态前 30% → 关
   ├─ 2.4 第三段（深度采集，通过前两段的帖子）：
   │      正文 + 标签 + 评论 + 购买扫描 + 作者主页
   ├─ 2.5 动态关键词扩展
   ├─ 2.6 休息 5-8s → 熔断检查 → 下一个词
3. 去重合并
4. 统计（账号频次 Top10 / 类型分布 / 购买信号 / 高收藏 Top10）
5. 输出（Markdown 报告 + CSV + 可选 Word）
6. 关闭 tab，输出文件路径
```

## 各步骤详细指引

### 1. 词表加载

**预设种子词（15 个）：**
```
核心词：猫爬架、猫别墅、通天柱、猫跳台、猫咪活动区
场景词：猫咪家具、猫柜、猫咪乐园、猫爬架推荐、猫别墅DIY
长尾词：猫爬架实木、猫爬架改造、猫别墅设计、猫爬柜、猫爬架怎么选
```

**排除词表（永不搜索，同时用于过滤内容关键词）：**
```
踩雷、避雷、智商税、闲置、翻车、不实用、后悔
```

**动态扩展规则（仅在用户选 A 全程时启用）：**
- 来源：搜索联想词 + 帖子标题高频词 + 评论区提及的品类词
- 准入条件（必须**全部**满足）：
  1. 含字根：猫/爬/跳/窝/架/柜/柱
  2. 不在排除列表中
  3. 在 3+ 条帖子标题或标签中出现
- 上限：每轮最多追加 **5 个**新词，总词表不超过 **20 个**
- 新词在结果中标记为"动态词"，标注来源

### 2. 搜索执行

**2.1 搜索操作**

每个关键词的执行步骤：

```
1. 打开小红书搜索页 URL: https://www.xiaohongshu.com/search_result?keyword=<编码后的关键词>
   （用 POST body 传入 /new 或 /navigate）
2. 等待页面完全加载（DOM 稳定，搜索结果显示）
3. 查找排序切换区域，点击"最新"标签
4. 等待排序切换完成，页面刷新
5. 开始滚动采集：
   for 轮次 in 1..10:
       采集当前可见的帖子卡片（标题/链接/点赞/评论/相对时间标签）
       向下滚动 ≈窗口高度的 80%（每次位置随机偏移 ±10%）
       wait 1.5-3s（随机）
       如果连续 2 轮没出现新帖子 → 停止滚动
   end
```

**从帖子卡片提取以下字段：**
```json
{
  "title": "标题文本",
  "link": "帖子 URL",
  "likes": 点赞数（数字，如卡片未显示则 null）,
  "comments": 评论数,
  "relative_time": "1个月前/3周前等相对时间文本"
}
```

**2.2 第一段预筛（卡片级，不增加页面开销）**

对采集到的列表做粗筛：

```
1. 时间过滤：
   相对时间标签含"刚刚""小时前""天前""周前"（且数字 ≤ 3）→ ❌ 跳过
   相对时间含"个月前""个月前"（且数字 ≥ 1）→ ✅ 候选
   注：这是粗筛，精度不够没关系，第二段会精确检查

2. 点赞过滤：
   取前 50%（以点赞数排序，无点赞数的视为 low）
   如果列表不足 30 条，跳过点赞过滤全部保留
```

**2.3 第二段筛（打开详情页，低成本检查）**

只有通过第一段筛的帖子才会开详情页：

```
for each 候选帖子:
    1. 打开帖子详情页（新 tab 或 navigate）
    2. 等待加载完成
    3. 提取精确发布时间 → 如果在 2026-01-10 之前 → 关 tab，跳过
    4. 提取收藏数 → 低于本轮前 30% 分位 → 关 tab，跳过
    5. 通过 → 进入第三段深度采集
end
```

**关于发布时间和收藏数的提取方式：**

小红书的发布时间位于详情页的某个区域（通常在作者信息附近），收藏数也显示在互动区域。使用 `/eval` 查询 DOM：

```javascript
// 参考选择器（实际 DOM 以页面为准，需要先用 eval 探索结构）
// 获取发布时间文本
document.querySelector('.date, .time, [class*="time"], [class*="date"]')?.innerText

// 获取收藏数
document.querySelector('[class*="collect"], [class*="save"], [class*="star"]')?.innerText
```

如果选择器拿不到，用正则从页面文本中提取：
```javascript
document.body.innerText.match(/(\d+)\s*分钟前/)  // 相对时间
document.body.innerText.match(/收藏\s*(\d+)/)    // 收藏数
```

**2.4 第三段（深度采集）**

只有通过第二段筛的帖子上这个步骤：

```
采集内容：
  1. 完整正文文案
     document.querySelector('#detail-desc, .note-scroller, [class*="content"]')?.innerText

  2. 所有话题标签（#xxx）
     document.querySelectorAll('[class*="tag"]') 或 从正文中用正则提取

  3. 作者昵称 + 作者主页链接
     作者区域通常在详情页顶部或底部
     需要构建作者主页 URL: https://www.xiaohongshu.com/user/profile/<user_id>

  4. 热门前几条评论
     小红书评论通常在详情页底部，可能需要滚动到底部触发加载
     for 评论采集：
         滚动到评论区位置
         wait 1-2s 让评论加载
         提取可见的前 N 条评论（评论者 + 内容 + 点赞数）
     如果评论区域需要点击"展开" → 先点击再采集

  5. 购买意向评论扫描（见第 3 节）

  6. 作者账号类型识别（见第 4 节）
```

**2.5 熔断检查**

每一步操作后检查：
- 本次执行总页面交互数 > 150 → 停止，输出阶段性结果
- 已开详情页数 > 40 → 停止，输出阶段性结果
- 超过 2 个词连续搜不到结果 → 提前终止（可能是被限流）

### 3. 购买意向评论引擎

评论采集到手后，逐条扫描：

**正向信号词库：**
```
高信号：买了、已下单、求链接、在哪买、多少钱、入手了、已购、
        有链接吗、怎么买、求团购、链接求、同款求、店铺求
中信号：种草了、求推荐、哪里入、什么牌子、这个好、想要、
        好好看、喜欢求、被安利了、想买
```

**负向抵消词库（命中任意一条 → 降级）：**
```
别买、避雷、后悔、退了、退货、踩雷、不推荐、智商税、闲置了、
质量问题、坏了、不值得、劝退、别入、避坑、翻车、差评
```

**判断逻辑：**

```
函数 assess_buying_intent(comment_text):
    正向命中 = 匹配正向词库的数量
    有负向 = 负向词库是否有匹配
    
    if 有负向:
        return "🟢 低"   // 可能是吐槽或劝退
    if 正向命中 >= 2:
        return "🔴 高"   // 强购买信号
    if 正向命中 == 1:
        return "🟡 中"   // 弱购买信号
    return "🟢 低"
```

如果该帖子的热评中有任何一条标记为 🔴 高，在最终输出中整条帖子的购买信号强度直接标 🔴。如果有 🟡 无 🔴 则标 🟡。

### 4. 账号类型识别

通过作者主页识别账号类型：

**蓝V 识别（满足任意一条即可判定）：**
1. 页面中存在企业认证标识（"企业认证""蓝V""品牌号"等文本）
2. 页面上有"商品橱窗"板块
3. 简介中含"品牌""企业""旗舰店""官方""专卖店"等字眼

**设计师识别（需要同时满足 ≥2 条）：**
1. 个人标签/类目中含"设计"（系统标签而非简介）
2. 简介含设计相关词：设计师、室内设计、空间设计、软装设计、全案设计
3. 主页无商品橱窗（排除纯商家）
4. 帖子标题含设计案例关键词：效果图、设计、方案、装修

**兜底策略：**
如果 DOM 选择器无法稳定定位蓝V标识，改为页面文本全文搜索：

```javascript
document.body.innerText.includes('企业认证') || 
document.body.innerText.includes('品牌号')
```

**识别结果标记：**
- 蓝V ✅ → 标记"蓝V"
- 设计师 ✅ → 标记"设计师"
- 设计师 ⚠️（仅满足 1 条）→ 标记"疑似设计师"
- 以上都不是 → 标记"个人账号"

### 5. 去重与统计

**去重规则：**
以帖子 URL 为唯一标识。同一帖子被多个关键词命中时，合并为一条记录，在"匹配关键词"字段中列出所有来源词。

**统计维度：**

```
1. 账号频次 Top10：
   - 统计每个作者在本轮采集中出现的总次数
   - 区分蓝V/设计师/个人分别排名
   - 说明：出现次数多 = 该账号内容覆盖面广，可能是重要竞品

2. 类型分布：
   - 蓝V 产出的帖子数及占比
   - 设计师产出的帖子数及占比
   - 个人账号产出的帖子数及占比

3. 购买信号分析：
   - 🔴/🟡/🟢 信号帖子的数量和占比
   - 哪个关键词带来的高信号帖子最多

4. 高收藏内容 Top10：
   - 按收藏数降序取前 10 条
```

## CDP 操作要点

### tab 管理
- 全程在后台 tab 操作，不干扰用户的浏览器
- 每次搜索用 `/new` 打开新 tab
- 搜完后用 `/close` 关闭 tab
- 任务完成后关闭所有创建的 tab

### 节奏控制
- 每次 DOM 操作后 wait 1.5-4s（随机，不固定！）
- 滚动之间 wait 1.5-3s
- 在不同关键词之间 wait 5-8s
- 用 `Math.random()` 生成间隔：`1500 + Math.random() * 2000`

### 反爬注意事项
- 优先使用 `/clickAt`（真实鼠标手势）而非 `/click`（JS 点击）
- 不固定滚动距离，每次 = 窗口高度 × (0.7 + Math.random() * 0.3)
- 不要一次开多个 tab 并行操作
- 某页面加载超过 15s 无响应 → 关 tab 重试 1 次 → 仍失败则跳过
- 如果连续收到空白页或验证码 → 停止所有操作，提示用户

### 注意：页面结构可能变化
小红书的前端 DOM 可能随时改版。SKILL.md 中给出的选择器是参考值。实操时：
1. 先用 `/eval` 打印页面结构，找到实际的数据元素
2. 再用针对性的选择器提取内容
3. 如果页面结构与预期不符，不要反复试，改策略

## 错误处理

| 场景 | 处理方式 |
|------|---------|
| 搜索结果为空 | 尝试 2 次 → 仍空则跳过该词，标记为"搜到 0 条" |
| 详情页 404 | 跳过该帖子 |
| 作者主页无法加载 | 跳过账号识别，标记"未知" |
| 评论区域未加载 | 尝试滚动到底部一次 → 仍无则标记"评论未获取" |
| CDP 断开 | 尝试重新连接 → 失败则提示用户重启浏览器 |
| 词表全跑完但收录 0 条 | 输出报告"本次未收录到符合条件的帖子"，给出可能原因 |
